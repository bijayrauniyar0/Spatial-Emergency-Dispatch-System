\chapter{System Design}

\section{System Architecture}

SEDS follows a three-tier containerized architecture separating presentation, application logic, and data persistence. The Next.js frontend, Node.js/Express backend, and PostgreSQL/PostGIS database each run as independent Docker containers orchestrated via Docker Compose. All inter-tier communication is strictly layered: the browser calls only the REST API, and the API is the sole consumer of the database.

\begin{itemize}
  \item \textbf{Frontend:} Next.js 16 with React 19, MapLibre GL for WebGL map rendering, Tailwind CSS, shadcn/ui components.
  \item \textbf{Backend:} Node.js 20 + TypeScript + Express REST API; Sequelize ORM; JWT authentication; Socket.io (planned).
  \item \textbf{Database:} PostgreSQL 16 with PostGIS 3.4 extension; GEOMETRY types for spatial data; GIST indexes for fast containment queries.
  \item \textbf{Infrastructure:} Docker Compose orchestrates all services; PostGIS container pre-loaded via init-postgis.sql.
\end{itemize}

\section{Database Schema}

The database comprises five tables managed by Sequelize ORM with PostgreSQL 16 and PostGIS 3.4.

\begin{itemize}
  \item \textbf{users:} id, name, email, password (bcrypt), role ENUM(admin/responder/citizen), oauth\_provider ENUM(local/google), verified BOOLEAN.
  \item \textbf{stations:} id, name, category ENUM(POLICE/FIRE/MEDICAL), location GEOMETRY(Point, 4326).
  \item \textbf{zones:} id, station\_id (FK \textrightarrow\ stations, CASCADE), boundary GEOMETRY(Polygon, 4326) with GIST index.
  \item \textbf{responders:} id, user\_id (FK \textrightarrow\ users, CASCADE), station\_id (FK \textrightarrow\ stations, CASCADE), status ENUM(AVAILABLE/BUSY/OFF\_DUTY).
  \item \textbf{incidents:} id, citizen\_id (FK \textrightarrow\ users), station\_id (FK \textrightarrow\ stations), responder\_id (FK \textrightarrow\ responders, nullable), category ENUM(POLICE/FIRE/MEDICAL), status ENUM(PENDING/RESPONDING/RESOLVED), location GEOMETRY(Point, 4326).
\end{itemize}
