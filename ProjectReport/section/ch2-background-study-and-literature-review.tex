\chapter{Background Study and Literature Review}

\section{Background Study}

Emergency dispatch in Nepal relies on telephone-based, human-operated coordination with no spatial decision support.
Dispatchers manually identify the nearest station by memory or paper map, causing delays that worsen outcomes in
time-critical incidents \cite{zlatanova2004gis}. Overlapping police, fire, and medical jurisdictions in Kathmandu
compound the problem.

PostGIS spatial queries resolve zone jurisdiction in milliseconds using \texttt{ST\_Contains} against GIST-indexed
polygon boundaries. SEDS replaces the manual lookup step with this query, instantly identifying which station's
zone contains the incident coordinate.

\subsection{Key Challenges in Manual Dispatch}

\begin{itemize}
  \item \textbf{Jurisdiction Lookup:} No automated way to determine which station covers a given location.
  \item \textbf{No Real-Time Routing:} Responders receive verbal directions with no road-network route guidance.
  \item \textbf{No Citizen Feedback:} Citizens have no visibility into responder location or estimated arrival.
  \item \textbf{Human Error:} Manual station selection under pressure leads to misassignment across zones.
\end{itemize}

\section{Literature Review}

The following works directly inform the design and technology choices of SEDS.

\begin{itemize}
  \item \textbf{OSRM (Luxen \& Vetter, 2011):} Introduces a contraction-hierarchy routing engine over OpenStreetMap
        data for sub-second road-network shortest-path queries; SEDS plans to integrate OSRM to compute turn-by-turn
        routes from an assigned station to the incident location. \cite{luxen2011realtime}

  \item \textbf{PostGIS in Action (Obe \& Hsu, 2021):} Covers spatial type design, GIST indexing, and
        \texttt{ST\_Contains}/\texttt{ST\_MakePoint} usage in PostgreSQL; SEDS stores zones as
        \texttt{GEOMETRY('Polygon', 4326)} with a GIST index for instant triage queries. \cite{postgis2023}

  \item \textbf{GIS for Emergency Management (Zlatanova et al., 2004):} Documents that spatial polygon containment
        lookups reduce manual dispatch assignment time from 47 seconds to under two seconds; motivates SEDS's core
        spatial triage design. \cite{zlatanova2004gis}

  \item \textbf{GeoJSON RFC 7946 (Butler et al., 2016):} Defines the JSON encoding for geographic features with
        mandatory EPSG:4326 coordinates; SEDS uses GeoJSON for all API responses, map data sources, and zone file
        uploads. \cite{json2019rfc}

  \item \textbf{MapLibre GL JS (2023):} Open-source WebGL map renderer that accepts GeoJSON sources directly; SEDS
        uses it for station point rendering, zone polygon rendering, and the admin polygon-drawing tool.
        \cite{maplibre2023}

  \item \textbf{JWT RFC 7519 (Jones et al., 2015):} Specifies compact, self-contained signed tokens for stateless
        authentication; SEDS issues JWTs in HTTP-only cookies and validates role claims in Express middleware for
        RBAC. \cite{jwt2015rfc}
\end{itemize}

No existing open-source platform combines PostGIS spatial triage, OSRM routing, and a React-based operator map
interface in a single self-hostable deployment; SEDS fills this gap for under-resourced municipalities.
